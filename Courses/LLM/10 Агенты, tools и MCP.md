# Агенты, tools и MCP

Агент выбирает следующее действие по состоянию; фиксированный pipeline следует заранее заданным шагам. Tool calling — запрос модели к приложению, а выполнение и выдача прав остаются обязанностью приложения. Структурная корректность вызова не означает, что действие разрешено.

## Как это работает

Для каждого tool нужны имя, схема входа, результат и политика ошибок. Проверяй allowlist, обязательные/лишние поля, типы, лимит шагов, таймаут и идемпотентность действий. MCP задаёт протокол обнаружения и вызова инструментов; это не замена аутентификации, авторизации или prompt security. Для операций записи отделяй предложение от исполнения. Human-in-the-loop полезен в конкретных точках принятия значимых решений, а не как украшение любого графа.

## Как применять и проверять

В учебной задаче валидируем вызов, но ничего не исполняем. Следующая практика — один безопасный read-only tool, затем ограниченный агент и тесты его остановки.

## Проверь понимание

1. Сформулируй основной контракт этой темы и один случай, когда он нарушается.
2. Приведи пример из своих проектов или объясни, почему тема там не применялась.
3. Какие данные/метрики понадобятся, чтобы проверить улучшение?
