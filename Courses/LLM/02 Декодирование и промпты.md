# Декодирование и промпты

Логиты — ненормированные оценки токенов. Softmax переводит их в распределение: pᵢ=exp(zᵢ/T)/Σexp(zⱼ/T). Для численной устойчивости сначала вычитают максимум логитов. Температура T>0 меняет резкость распределения; это не мера фактической достоверности ответа.

## Как это работает

Greedy выбирает максимум, sampling выбирает случайно; top-k и top-p ограничивают набор кандидатов. Промпт задаёт задачу, контекст, формат результата и примеры. Few-shot помогает определить контракт, но не заменяет данные и тестирование. Структурированный вывод надо валидировать по схеме. Даже корректный JSON может содержать неправильные факты. Разделяй инструкции и пользовательские/извлечённые данные; текст документа не получает права менять политику приложения.

## Как применять и проверять

Менять за один эксперимент один фактор: промпт, контекст или декодирование. Сохранять версию промпта и конфигурацию. Не обещать абсолютную воспроизводимость реального API по одному seed.

## Проверь понимание

1. Сформулируй основной контракт этой темы и один случай, когда он нарушается.
2. Приведи пример из своих проектов или объясни, почему тема там не применялась.
3. Какие данные/метрики понадобятся, чтобы проверить улучшение?
