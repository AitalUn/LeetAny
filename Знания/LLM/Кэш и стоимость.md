# Кэш и стоимость

Кэш может уменьшить latency и стоимость только если ключ отражает все факторы результата. Для LLM это как минимум модель/версия, сообщения, конфигурация и версии контекста; для многопользовательской системы также область прав доступа. Хэш лишь компактно представляет ключ, а не исправляет пропущенные поля.

## Как это работает

Каноническая сериализация делает порядок ключей JSON несущественным. TTL ограничивает устаревание, но при удалении документа или изменении прав может потребоваться явная инвалидизация. Нельзя объединять данные пользователей без политики. Для embeddings и готовых ответов нужны разные ключи. Считай input/output tokens, cache hit rate, затраты по запросу и качество; ускорение ценой устаревших ответов не является бесплатным улучшением.

## Как применять и проверять

В учебной задаче функция хэширует полный переданный config. В реальном сервисе ответственность за включение prompt/index/tenant versions должна быть закреплена отдельным контрактом.
