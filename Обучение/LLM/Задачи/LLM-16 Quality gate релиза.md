# LLM-16. Quality gate релиза

Теория: [[Знания/LLM/MLOps, тестирование и выпуск|MLOps, тестирование и выпуск]] · [[Обучение/LLM/Учебник|Учебник]]

## Задача

Оба словаря содержат ровно quality (число 0..1) и p95_ms (число≥0). min_quality — 0..1, max_p95≥0; все числа конечны и без bool, иначе ValueError. Верни True только если candidate.quality≥max(baseline.quality,min_quality) и candidate.p95_ms≤max_p95. Равенство порогу проходит. baseline.p95_ms используется для валидации входа, но не задаёт порог. Это gate качества/latency, а не полный production release.

### Пример

`({"quality":0.8,"p95_ms":100},{"quality":0.85,"p95_ms":120},0.8,150) → True`

### Ограничения

Python 3.10+, только стандартная библиотека. Без сети, API-ключей и загрузки моделей. Чистая функция: не менять аргументы и не выполнять файловые/сетевые действия. Допускаются импорты стандартной библиотеки. Приведи оценку сложности по времени/памяти. Данные тестов открыты — не подгоняй решение под конкретные значения.
