# Учебник LLM: теория и практика

Основная теория хранится в Знания/LLM один раз; здесь — порядок, задачи и прогресс. Все задачи пока не решены. Для старта не нужны GPU, платные API или установка ML-библиотек.

## Как учиться

1. Открой плагин LeetAny и выбери задачу. Сначала прочитай связанную теорию.
2. Напиши решение в Python-блоке заметки и свои проверки.
3. Запусти тесты, исправь ошибки.
4. Запроси ревью кода. Обсуди компромиссы и исправь замечания.
5. Отметка о навыке появляется после решения и объяснения; не после чтения страницы.

## После маленьких задач: законченные мини-проекты

### A. RAG benchmark (качество, retrieval, MLflow)
Вход: 12–20 разрешённых к использованию текстовых документов, минимум 30 вопросов с doc_id-эталонами, среди них минимум 5 неотвечаемых; фиксированный document-level dev/test split. Реализуй парсинг, chunking, lexical baseline и один dense retriever; сравни dense, RRF и RRF+reranker. Генератор сначала fake, затем опционально реальная локальная модель. Выход: JSON/CSV метрик retrieval, корректности/цитат/отказов, latency и стоимости; versioned config и run_id. В MLflow сохрани параметры, метрики и артефакты. Готовность: один документированный запуск, неизменяемый test, разбор минимум пяти ошибок и отсутствие неподтверждённых выводов. Это отдельный проект, он не выполнен после функций-метрик.

### B. Сервис и тесты (FastAPI, Docker, Git, Linux, CI)
Один endpoint POST /answer с query, ответом, sources и request_id. Зависимость генератора подменяется fake; вход валидируется, ошибки provider/timeout дают заранее описанные HTTP-ответы. Добавь unit/integration тесты, Dockerfile без секретов и CI, который запускает проверки. Готовность: запуск по README, воспроизводимые успешный запрос и ошибка, тесты без сети, понятный rollback. Linux-практика: запуск, логи, диагностика процесса; не считать её освоенной только из-за Docker.

### C. Ограниченный агент (LangGraph/LangChain, MCP)
Один агент с двумя read-only tools: поиск по корпусу и чтение найденного документа. Ограничение шагов и времени, схема вызова, явный список разрешённых инструментов. Один tool можно предоставить через MCP. Минимум 8 сценариев: успех, неизвестный tool, неверные типы, недоступность, отсутствие данных, лимит шагов, инструкция внутри документа и запрет операции записи. Готовность: трасса шагов и воспроизводимые результаты; оценить не только финальный ответ, но и корректность действий.

### D. Развёртывание и специализации
Выбери одну ветку по целевой вакансии: (1) inference — сравни vLLM или ONNX с baseline на фиксированной нагрузке/железе; (2) LoRA — сравни prompting/RAG baseline и небольшой адаптер по отложенному набору и деградациям; (3) Kubernetes — Deployment/Service, probes, resource limits, rollout/rollback в локальном кластере; (4) Airflow — ежедневный идемпотентный ingestion DAG с повторным запуском без дублей. Для каждой ветки нужны README, версия окружения, измеримый критерий и воспроизводимый отчёт. Не надо делать четыре ветки одновременно.
